# ページの凍結 (#freeze) の仕様 (#16)

書き換えされたくないページを保護するための仕組み。
ページ本文の**先頭行**に `#freeze` と書いておくと、そのページは
「凍結」され、書き換えの際に管理者であることが必要になる。

## 使い方

KonaWiki 記法のページでは、先頭行に次のように書く。

```text
#freeze
■重要なお知らせ
(本文...)
```

Markdown のページでは、先頭行に `#freeze` または `!!freeze` と書く
(どちらでも凍結として扱われる)。

## 挙動

- 凍結されたページは、管理者だけが保存できる。一般ユーザーが保存しようと
  すると「このページは凍結されています。編集できるのは管理者だけです。」
  と表示され、保存されない。本文を空にしてページを削除する操作も同様に
  できない。
- 凍結されていないページを新たに凍結する (先頭行に `#freeze` を追加して
  保存する) 操作も管理者だけが行える。一般ユーザーが `#freeze` を含む
  本文を保存しようとすると、凍結できない旨が表示され、保存されない。
- 管理者は凍結されたページをそのまま編集でき、`#freeze` を取り除いて
  保存すれば凍結を解除できる。
- 編集画面を開いた時点で、凍結されたページにはその旨の案内が表示される
  (一般ユーザーには「編集できるのは管理者だけ」、管理者には
  「管理者なので編集できる」と表示する)。
- チェックは保存経路 (通常フォーム / Ajax / Git 保存) のすべてに効く。
  ページの書き込みは `kona3_trywrite()` を通るため、そこで一括して判定する。

## 凍結の判定

- 判定は `kona3isFrozenPageText()` (本文テキスト) と
  `kona3pageIsFrozen()` (保存済みページ) で行い、表示用パーサーを
  介さない。そのため記法モード (.txt / .md) によらず同じように働く。
- 有効なのは**先頭行だけ**。本文の途中に `#freeze` と書いても凍結には
  ならない (引用やコード例として書けるようにするため)。
- 先頭行として認める形式は `#freeze`、`#freeze(...)`、`!!freeze`、
  `!!freeze(...)`、`♪freeze` で、前後の空白と末尾の `;` は許容する。
  BOM と CRLF 改行にも対応する。
- `#freezeXXX` のような別名は凍結とはみなさない。

## 表示

- `#freeze` プラグイン (`kona3engine/plugins/freeze.inc.php`) は表示上は
  何も出力しない (HTML コメント `<!-- #freeze -->` だけを残す)。
  凍結の効力は表示ではなく編集時のチェックで発揮される。
- Markdown パーサーでは、行頭の `#freeze` は見出しではなくプラグイン
  として解釈する (空白なしの `#freeze` は CommonMark でも見出しには
  ならない)。
