# 静的Wiki出力 仕様

- 関連Issue: [#267 静的サイト出力を主力にするように修正する](https://github.com/kujirahand/konawiki3/issues/267)
- 状態: 仕様策定中（Draft）
- 出力先について: Issue 本文では `public` フォルダとしていたが、Issue コメントの仕様案に従い既定を `dist/` とする（`static_outdir` で `public` 等にも変更可能）。

## 1. 目的と基本方針

- 閲覧するだけなら PHP を不要にする。Wiki の全公開ページを静的 HTML として `dist/` に書き出し、任意の静的ホスティング（Apache / nginx / GitHub Pages / Netlify / S3 など）で配信できるようにする。
- **編集・管理は従来どおり PHP 版で行い、閲覧は静的版を主とする**。PHP 版の閲覧機能（`show` アクション）は互換のため残す。
- 静的出力は既存の描画処理（パーサー・テンプレート・スキン・プラグイン）を再利用して生成し、PHP 版と見た目を揃える。描画ロジックを二重に持たない。
- ビルドは「未ログイン（匿名）ユーザーが見える内容」で行う。ログイン時だけ見える情報は一切出力しない。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| Wiki名 | ページの論理名。例: `使い方/基本操作`。`/` は階層区切り |
| 階層名 | Wiki名を `/` で分割した各要素。例: `使い方`、`基本操作` |
| 物理名 | 階層名をファイル名用にエンコードしたもの |
| 出力パス | `dist/` 配下の実ファイルのパス |
| 公開URL | 静的サイト上でページを指すURL |
| ベースURL | 静的サイトの公開ルート。設定 `static_base_url` |

## 3. 出力ディレクトリ構成

出力先は既定で `dist/`（設定 `static_outdir` で変更可）。Wikiの階層を維持し、各ページを `index.html` として出力する。

```text
dist/
├── index.html                 # FrontPage
├── 404.html                   # 存在しないページ用
├── sitemap.xml                # 公開ページ一覧（static_base_url が絶対URLの場合のみ）
├── はじめに/index.html
├── 使い方/
│   ├── index.html             # 「使い方」ページ（無ければディレクトリ一覧ページ）
│   └── 基本操作/index.html
└── _kona3/                    # システム予約領域（ページと衝突しない。5.3 参照）
    ├── skin/<skin名>/...      # スキンのCSS/JS/画像
    ├── resource/...           # kona3engine/resource のCSS/JS等
    └── files/...              # data/ 内の添付ファイル（画像・PDF等）
```

### Wiki名と出力パス・公開URLの対応

| Wiki名 | 出力ファイル | 公開URL（ベースURL `/` の場合） |
| --- | --- | --- |
| `FrontPage`（設定上のトップページ） | `dist/index.html` | `/` |
| `はじめに` | `dist/はじめに/index.html` | `/%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB/` |
| `使い方/基本操作` | `dist/使い方/基本操作/index.html` | `/使い方/基本操作/`（実際は各階層を `rawurlencode`） |
| `開発/API仕様` | `dist/開発/API仕様/index.html` | `/開発/API仕様/`（同上） |

- FrontPage は `dist/index.html` のみに出力し、`dist/FrontPage/index.html` は出力しない。FrontPage へのリンクはすべてベースURLになる。
- 下位ページを持つページ（例: `使い方` と `使い方/基本操作`）は、`使い方/index.html` と `使い方/基本操作/index.html` として自然に共存する。

## 4. 物理名のエンコード規則

### 4.1 前処理

1. Wiki名を UTF-8 として検証する。不正なバイト列はエラー。
2. Unicode 正規化 NFC を適用する（`Normalizer::normalize($name, Normalizer::FORM_C)`）。macOS で作成された NFD のファイル名対策。
   - **NFC 正規化は必須**とし、`intl` 拡張（`Normalizer`）が無い環境ではビルドを開始せずエラーにする。正規化を省くと NFC の `é` と NFD の `e` + `U+0301` が別名として扱われ、正規化するファイルシステム上で同じ出力先を上書きし得るため。
3. `/` で階層名に分割する。

### 4.2 階層名ごとの変換

次の文字を **`_HH`**（UTF-8 の各バイトを大文字16進2桁）に置き換える。それ以外（日本語を含む非ASCII文字、英数字、その他の記号）はそのまま使う。

| 対象 | 理由 |
| --- | --- |
| `_` | エスケープ文字自体。曖昧さ防止（`foo_bar` → `foo_5Fbar`） |
| `%` | URLデコードとの衝突防止 |
| `< > : " \ \| ? *` | Windows でファイル名に使えない |
| 制御文字 `0x00`–`0x1F`、`0x7F` | ファイル名・URLに不適 |
| 先頭の `.` | 隠しファイル化（`.htaccess` 等）や `.`/`..` との混同を防ぐ |
| 末尾の空白・`.` | Windows で除去される |
| 先頭の空白 | 視認性・誤操作防止 |

- Windows 予約名（`CON` `PRN` `AUX` `NUL` `COM1`–`COM9` `LPT1`–`LPT9`。大文字小文字を問わず、`CON.txt` のように拡張子付きも含む）に該当する場合は、**先頭1文字を `_HH` にエンコード**する（例: `CON` → `_43ON`）。
- 変換は単射（異なる階層名は必ず異なる物理名になる）であり、`_HH` を復号すれば元の階層名に戻せる。

### 4.3 拒否条件（ビルドエラー）

- 空の階層（`a//b`、先頭・末尾の `/`）
- 階層名が `.` または `..`
- 不正な UTF-8
- 物理名が 1 階層あたり **200 バイト**を超える
- 出力パス全体（`dist/` からの相対）が **1000 バイト**を超える

長すぎる場合に切り詰めやハッシュ化はしない（衝突や不可逆化を避けるため）。該当ページ名をエラーとして報告する。

### 4.4 変換例

| Wiki名 | 出力ファイル |
| --- | --- |
| `質問?回答` | `dist/質問_3F回答/index.html` |
| `A:B` | `dist/A_3AB/index.html` |
| `100%完成` | `dist/100_25完成/index.html` |
| `foo_bar` | `dist/foo_5Fbar/index.html` |
| `Windows/設定` | `dist/Windows/設定/index.html` |
| `.htaccess` | `dist/_2Ehtaccess/index.html` |
| `con` | `dist/_63on/index.html` |
| `末尾.` | `dist/末尾_2E/index.html` |

### 4.5 システム予約領域

`_` は常に `_HH` にエンコードされるため、**物理名が `_` の直後に16進2桁以外で始まるもの**はページから生成されることがない。この性質を利用し、`dist/_kona3/` をシステム予約領域（アセット・添付ファイル）とする。`404.html` や `sitemap.xml` などルート直下の単独ファイルは、ページが必ずディレクトリ（`<名前>/index.html`）になるため衝突しない。

## 5. 公開URL

- 公開URLは「ベースURL ＋ 物理パスの各階層を `rawurlencode()` して `/` で連結 ＋ 末尾 `/`」とする。
  - 例: `使い方/基本操作` → `{base}%E4%BD%BF%E3%81%84%E6%96%B9/%E5%9F%BA%E6%9C%AC%E6%93%8D%E4%BD%9C/`
  - 例: `foo_bar` → `{base}foo_5Fbar/`
- ベースURL（`static_base_url`）
  - 既定値は `/`。サブディレクトリ公開時は `/wiki/` や `https://example.com/wiki/` を指定する。
  - 末尾の `/` は自動補完する。
- ページ内アンカー（見出しリンク `#h...`）は公開URLの後ろに付ける。
- 末尾 `/` 形式のURLはWebサーバーのディレクトリインデックス（`index.html`）機能を前提とする。`file://` での直接閲覧は対象外。

## 6. 衝突検出

異なるWiki名が同じ出力先になる場合は、**上書きせずビルドエラー**とし、衝突したWiki名の組をすべて報告する。

- 比較キー: 物理パスに対して「NFC 正規化 → ケースフォールディング（`mb_convert_case($s, MB_CASE_FOLD, 'UTF-8')`）→ 再度 NFC 正規化」を行ったもの。
  - 大文字小文字を区別しない、または Unicode 正規化を行うファイルシステム（Windows / macOS 既定）でも安全にする。
  - NFC 正規化は 4.1 のとおり必須で、`intl` が無い環境ではここに到達しない。
- 例: `About` と `about`、NFC と NFD で表記が異なる同名ページ。
- 添付ファイル（`_kona3/files/` 以下）も同じキーで衝突を検出する。

## 7. ページ種別ごとの出力

| 種別 | 判定 | 出力 |
| --- | --- | --- |
| KonaNotation ページ | `.txt`（メタ `mode` 優先） | 通常ページとして HTML 化 |
| Markdown ページ | `.md`（メタ `mode` 優先） | 通常ページとして HTML 化 |
| ディレクトリのみ | ページファイルが無く、ディレクトリがある | `#ls` 相当の一覧ページを生成 |
| エイリアス | 本文に `!!alias(...)`、または `data/alias-show.json` に定義 | リダイレクト用 HTML（`<meta http-equiv="refresh">` ＋ `<link rel="canonical">` ＋ リンク）。循環・段数超過は警告し出力しない |
| 添付ファイル | 画像・PDF・Office 等（`allow_upload_ext` と `image_pattern` の拡張子。ただし 14章の拒否リストに該当するものは除く） | `dist/_kona3/files/` 以下に階層を維持し、4章の規則でエンコードしてコピー。ページとしては出力しない |
| その他 | 上記以外 | 出力しない |

- ページの選択（`.txt`/`.md` 両方ある場合の優先度など）は PHP 版の `kona3show_detect_file()` と同じ規則に従う。
- `enc_pagename` が有効な環境では、`data/` 内のファイル名を復号してからWiki名として扱う。

## 8. リンクとURLの変換

静的出力中は `static_mode` フラグを立て、URLを生成する既存関数の結果を切り替える。

| 関数 / 箇所 | PHP版 | 静的版 |
| --- | --- | --- |
| `kona3getPageURL($page)`（`show`） | `index.php?Page` | `kona3getStaticURL($page)` |
| `kona3getPageURL($page, 'show')` 以外のアクション | `index.php?Page&edit` 等 | 出力しない（8.1） |
| `kona3getSkinURL()` | `index.php?file&skin` | `{base}_kona3/skin/<skin>/file` |
| `kona3getResourceURL()` | `index.php?file&resource` | `{base}_kona3/resource/file` |
| `ref` 等の添付リンク（`&data`） | `index.php?path&data` | `{base}_kona3/files/<encoded>` |
| `[[Wiki名]]`、`[[表示:Wiki名]]`、Markdownリンク | `index.php?Wiki名` | `kona3getStaticURL(Wiki名)` |
| パンくず（`kona3getPageTitleLink`） | 同上 | 同上 |

### 8.1 動的URLの扱い

- 静的版で、`show` 以外のアクション（`edit` `login` `search` `plugin` など）へのリンクは生成しない。テンプレートだけでなく、**`show` アクションやプラグインが HTML を組み立てる箇所も対象**とする。現状把握している箇所:
  - `action/show.inc.php` のタグ表示（`kona3getPageURL($page, 'plugin', '', 'name=tags&tag=...')` と `name=taglist`）: 静的モードでは、タグ名をリンクなしのテキストで出力する。フェーズ3でタグ一覧ページ（`_kona3/tags/`）を生成する場合はそこへのリンクにする。
  - `comment` `tags` `taglist` など、`plugin` アクションや POST 先を含むプラグイン: 10章の分類に従う。
- 漏れを防ぐため、ビルド時に各ページの HTML を検査し、相対の `index.php?` や `kona3conf['scriptname']` を含むURL（`href` `src` `action` 属性）が残っていればビルドエラーにする（`static_php_url` で始まる絶対URLは許可）。
- PHP版への導線（例: 「編集する」リンク）を残したい場合のために、設定 `static_php_url`（PHP版のURL）を用意する。指定時のみ、フッターに PHP 版へのリンクを出す。
- 存在しないページへのリンクは、`<span class="kona3_nolink">表示名</span>` として出力し、ビルド警告に記録する。

## 9. テンプレートの扱い

- `show.html` を流用し、`static_mode` のときは以下を出力しない。
  - 編集ボタン、ログインバー、文字数カウンタ
  - 編集トークンや CSRF トークンを含むフォーム
- `MenuBar`、`allpage_header`、`allpage_footer` はビルド時に展開して埋め込む。
- `sw.js`（Service Worker）は静的版では登録しない。
- 静的版専用の差分が大きくなった場合は `static_show.html` を別途設ける。

## 10. プラグインの扱い

プラグインは次の3分類で扱う。分類は各プラグインの定義に持たせず、既定の一覧（`kona3static.inc.php` 内）と設定 `static_plugin_disallow` で管理する。

| 分類 | 静的版での動作 | 対象（初期案） |
| --- | --- | --- |
| A. そのまま利用 | ビルド時に実行した結果をそのまま出力 | `code` `filecode` `csv` `tsv` `column` `footnote` `chapter` `include` `ls` `image` `ref` `mathjax` `tex` `mermaid`（描画のみ） `markdown` `md` `html` `br` `clear` `rem` `summary` `qrcode` `color_talk` など |
| B. ビルド時のスナップショット | ビルド時点の内容で固定して出力（更新はリビルド時） | `recent` `recent_meta` `tag` `tags` `taglist` `filelist` `countpages` |
| C. 静的版では無効 | 何も出力しない（または「この機能は静的版では利用できません」と表示） | `comment` `counter` `popular` `iflogin`（未ログイン側の内容のみ出力） `nako3`（実行系） `sakuramml_sf` `htmlshow`、その他 POST や Ajax を伴うもの |

- B 分類のプラグインを含むページは「揮発ページ」としてマニフェストに記録し、差分ビルドでも毎回再生成する（12.3 参照）。
- `tags` / `taglist` が生成するタグ一覧ページへのリンクは、静的版では `dist/_kona3/tags/` 以下に一覧ページを生成するか、リンクを外す（フェーズ3で決定）。
- ビルド中は `kona3isLogin()` が必ず FALSE を返すようにする。

## 11. 公開対象と除外

### 出力しないもの

- `wiki_private` が有効な Wiki 全体。ビルドを拒否し、強制オプションは設けない。静的出力には認証の仕組みが無く、非公開内容を書き出すと公開先のアクセス制御に依存した情報漏えいになるため。非公開 Wiki を閲覧させたい場合は PHP 版を使う。
  - **非公開にしたときは、生成済みの出力を無効化する。** `wiki_private` が有効な状態で、設定の保存・生成の実行・ページの保存のいずれかが行われたとき、マニフェストに記録済みの出力ファイル（ページ、添付ファイル、アセット）をすべて削除する（12.8）。新規の生成は行わない。
  - 設定画面で `wiki_private` を有効にして保存すると、その場で削除を実行し、削除した件数を画面に表示する。
  - 出力先の外側（CDN、公開先へ転送済みのコピーなど）に残った分は、このWikiからは消せないため、利用者の運用で削除する。設定画面の警告文にもその旨を書く。
- `data/` 内の `.` で始まるファイル・ディレクトリ（`.meta/`、`.git/` など）
- システムファイル: `alias-show.json` などの設定用 JSON
- `private/`、`cache/`、`kona3engine/` の内容（アセットとして明示的にコピーするもの以外）
- 7章で「出力しない」とされた種別、10章 C 分類のプラグインの出力
- シンボリックリンク（たどらない）

### 個別ページの除外

- メタデータ（`.meta/ページ名.json`）に `"static": false` を指定したページは出力しない。
- 設定 `static_exclude`（Wiki名のプレフィックス一覧）に該当するページは出力しない。例: `["下書き/", "MenuBar"]`。
  - `MenuBar` は既定で除外する（各ページに埋め込まれるため単独ページは不要）。

除外ページへのリンクは「存在しないページへのリンク」と同じ扱いにする（8.1）。

## 12. 生成のタイミングと方式

静的ファイルの生成は **設定 `static_enable`（既定: オフ）** で有効にする。オフのときは何も生成せず、PHP 版の動作は従来と変わらない。オンのときの動作は次の3つ。

| # | 契機 | 生成範囲 |
| --- | --- | --- |
| 1 | ページの編集（保存）時 | 保存した1ページ |
| 2 | マイページの管理者メニューの「静的ページを生成」ボタン | 全ページ（差分生成。12.3） |
| 3 | 同メニューの「すべて再生成」ボタン | 全ページ（差分判定なし） |

CLI（`php script/build_static.php [--full]`、`just build`）も同じ処理を呼び出す。CLI は `static_enable` がオフでも手動実行を許可する。

### 12.1 出力先と書き込み方式

- 出力先 `{out}` は設定 `static_outdir`（文字列。既定 `dist`）。インデックスディレクトリからの相対パス、または絶対パスで指定できる。
- 出力先が存在しなければ作成する（親ディレクトリが存在する場合のみ）。
- 公開ディレクトリを直接更新する。**各ファイルは同じディレクトリ内の一時ファイルに書き出してから `rename()` で置き換える**ため、読み出し側が書きかけのファイルを見ることはない。サイト全体の一貫性は、全体生成が終わるまで「ページごとに新旧が混在する」状態を許容する（結果整合）。
- 全体生成で、マニフェストに記録済みなのに今回の対象から外れたページ（削除・非公開化・リネーム前の名前）の出力ファイルは、全体生成の最後に削除する。**マニフェストに無いファイルやディレクトリは削除しない**（出力先に利用者の他のファイルがあっても安全）。
- **ディレクトリの削除**: マニフェストには、生成のために**この機能が新しく作ったディレクトリ**（`dirs`）を記録する。ファイルを削除した結果、記録済みのディレクトリが空になった場合に限り、そのディレクトリを削除する。生成の前から存在していたディレクトリ、記録のないディレクトリ、出力先 `{out}` そのものは、空になっても削除しない。
- **既存ファイルの上書き保護**: 書き込み先のパスに既にファイルがある場合、次のどちらかのときだけ置き換える。
  1. そのパスがマニフェストに記録済みである（この機能が生成したファイルである）。
  2. 添付ファイルとアセットのみ: 既存ファイルの内容が、これから書き込む内容と**バイト単位で同一**である。置き換えずに「自分のファイル」としてマニフェストに記録する。
  それ以外（利用者が置いたファイルと同じパス）は上書きせず、そのファイルの生成をエラーにして中止し、パスを報告する。書き込み先がディレクトリ（またはその逆）になる場合もエラーにする。
  - **ファイルの内容や名前（目印のコメントなど）を所有権の根拠にしない。** 利用者が同じ内容を置けば通過できてしまうため、所有権はマニフェストの記録だけで判断する。
- **マニフェストを失った場合の復旧**: マニフェストが無い（`cache/` を消したなど）状態では、出力先の既存ファイルはすべて「利用者のファイル」として扱われ、同じパスへの生成はエラーになる。管理者が明示的に復旧するための手段として、CLI のみに `php script/build_static.php --adopt` を設ける。
  - 実行すると、これから生成するパスのうち、既存ファイルと衝突するものを一覧表示し、`--yes` が無ければ確認を求める（管理者の明示的な同意を所有権の根拠とする）。
  - 同意された場合に限り、衝突したファイルを上書きして生成し、マニフェストに記録する。ディレクトリの記録（`dirs`）には、このとき存在しなかったものだけを加える。
  - 管理画面のボタンからは実行できない。
- 出力先の安全確認は 14章。

### 12.2 編集時の1ページ生成

- ページの保存が成功した後に、そのページだけを生成する。保存したページが静的出力の対象外（11章）なら、生成せず、既存の出力があれば削除する。
- ページのリネーム・削除では、旧名の出力ファイル（マニフェスト記録済みのもの）を削除する。
- **生成に失敗してもページの保存は成功扱いにする。** エラーは `cache/static_error.log` に記録し、編集画面には警告メッセージを1行出す。
- 1ページ生成は、マニフェスト上のパスと照合して衝突検出する（6章）。衝突する場合はそのページを書き出さず、エラーを記録する。
- 他のページへの影響（`ls` `recent` などの一覧系、そのページへ新規にリンクしているページの未存在表示）は、このタイミングでは更新しない。次の全体生成（差分）で反映される。
- 描画は匿名ユーザーとして行う（編集中の本人のログイン状態は一時的に無効化し、描画後に戻す）。
- `wiki_private` が有効な場合は生成しない（11章）。

### 12.3 差分生成（高速）

ファイルの内容は読まず、更新日時（mtime）の比較だけで判定する。

- **ページ**: ソース（`data/` の `.txt` / `.md`）の mtime が、出力 `index.html` の mtime より新しい、または `index.html` が存在しない場合に再生成する。メタデータ（`.meta/ページ名.json`）の mtime がソースより新しい場合は、そのメタデータの mtime を使う（2つの新しい方を比較する）。
- **添付ファイル**: ソースの mtime が出力より新しい、または出力が存在しない場合にコピーする。
- **全体の入力**: 次のいずれかが前回の全体生成より新しい、または変わった場合は、全ページを再生成する。
  - 設定ファイル（`private/kona3conf.json.php`）の mtime
  - `MenuBar` ページのソースの mtime
  - スキンのディレクトリと resource のファイルの最大 mtime、およびスキン名
  - エンジンのバージョン
  - 前回の全体生成の時刻は `cache/static_manifest.json` の `built_at` に記録する。
- **揮発ページ**（10章の B 分類のプラグインを含むページ）は、ページの追加・削除・リネームがあった場合、またはB分類の対象データが変わった場合は再生成する。差分の判定が難しい間は、揮発ページを毎回再生成する。
- ページの追加・削除は、`data/` の走査結果とマニフェストの差で検出する。走査（ディレクトリ一覧と `stat`）のみで、ページ内容は読まない。
- 出力できたファイルには、再生成のたびに mtime が現在時刻に更新される。その結果、次回の比較で「出力が新しい」状態になる。
- **失敗の記録（再試行）**: マニフェストの各ページには状態 `state`（`ok` / `failed` / `stale`）を持たせる。
  - 生成に失敗したページは `failed` とし、旧出力は残す。`failed` と `stale` のページは、ソースと出力の mtime に関わらず、次の生成で必ず再試行する。成功した時点で `ok` にする。
  - 「全体の入力」の変化（設定・`MenuBar`・スキンなど）を検出したときは、まず**全ページを `stale` にしてマニフェストを保存**してから生成を始める。各ページが成功するたびに `ok` に戻す。途中で失敗・中断しても `stale` が残るため、次回の差分生成で再試行される。
  - 全体の入力の記録（`built_at`、スキン名など）は、全ページが `ok` になったときだけ更新する。
  - 1ページ生成（編集時）で失敗した場合も、そのページを `failed` にする。
- 既知の制約: mtime を保存したままのコピー・復元や、時計のずれ、1秒以内の連続更新は検出できない。その場合は「すべて再生成」ボタンで復旧する。

### 12.4 全体生成の手順

1. ビルドロックを取得する（12.7）。
2. 出力先の安全確認（14章）。
3. 公開対象ページを列挙し、物理パスを計算し、衝突を検出する（エラーがあれば中止し、何も書き出さない）。
4. 差分判定（12.3）で、再生成する対象を決める（「すべて再生成」では全ページ）。
5. 対象のページを描画して書き出す（12.1 の方式）。
6. アセット（スキン、resource、添付ファイル）を同様に書き出す。
7. `404.html`、`sitemap.xml` を生成する。
8. マニフェストに記録済みで今回の対象から外れた出力を削除し（12.1）、マニフェストを更新する。全体の入力の記録は、全ページが `ok` のときだけ更新する（12.3）。

ページ単位のエラーは、そのページの出力を更新せず（`failed` として記録し）、残りの生成は続ける。生成の最後に、エラー・警告の一覧を表示する（警告は存在しないページへのリンクなど）。衝突や出力先の安全確認のエラーは、全体を中止する。

### 12.5 マイページ（管理者メニュー）

マイページ（`user.html`。メールアドレスのボタンを押した後の画面）の管理者メニューに、管理者（`kona3isAdmin()`）のときだけ、次のボタンを表示する。生成系と削除系で表示条件が異なる。

| ボタン | 表示条件 |
| --- | --- |
| 「静的ページを生成」（差分生成） | `static_enable` が有効 |
| 「すべて再生成」 | `static_enable` が有効 |
| 「静的出力を削除」（12.8） | マニフェストに出力が記録されている（`static_enable` の値に関わらない） |

- 管理者でなければ、どのボタンも表示せず、`static` アクションの呼び出しも拒否する。
- 生成系のボタンは、`static_enable` が無効な状態で `static` アクションが呼ばれても実行しない。削除は、マニフェストに出力が記録されていれば `static_enable` が無効でも実行できる。
- 押すと、新規アクション `static` を POST で呼び出す。CSRF トークン（`edit_token`）を必須にする。GET では実行しない。
- 実行後、生成したページ数・スキップしたページ数・削除したファイル数・エラーと警告の一覧を表示する。
- 実行中は他のビルドと同時に動かない（12.7）。

### 12.6 グローバル状態の扱い

既存の描画処理は `$kona3conf`（`css`、`js`、`header.tags`、`page` など）やプラグイン内の `static` 変数にページ単位の状態を積み上げる。複数ページを1プロセスで描画するため、次の対策をとる。

- ページごとに `$kona3conf` を開始時のスナップショットに戻してから描画する。
- `exit` / `header()` を呼ぶ処理（エイリアスのリダイレクト、`kona3error()` など）は、静的モードでは例外を投げて呼び出し元で処理する形に改める。
- 描画結果は出力バッファで受け取り、文字列として返す関数 `kona3show_render($page)` を `show` アクションから切り出す。`show` アクション自体もこの関数を使う。
- 編集時の1ページ生成（12.2）でも、編集リクエストの `$kona3conf` を壊さないよう、生成の前後で保存・復元する。

### 12.7 排他制御とマニフェストの更新

- 全体生成と1ページ生成は、`cache/static_build.lock` に対する `flock(LOCK_EX)` でロックを取得してから書き込む。
  - 1ページ生成（編集時）は短時間なので、最大5秒待つ。取得できなければ、ページ名を pending に追記して終了する（下記）。
  - 全体生成（ボタン・CLI）は待たず、ロックが取れなければ「生成実行中」としてエラーを返す。
- **pending の排他**: pending は、ビルドロックとは別のロック `cache/static_pending.lock`（`flock(LOCK_EX)`）で保護する。
  - 追記（編集処理側）: pending ロックを取得 → `cache/static_pending.json` に1行1ページ名で追記 → 解放。
  - 取り込み（ビルド側。ビルドロックを保持した状態で行う）: pending ロックを取得 → `static_pending.json` を `static_pending.<ビルドID>.json` に `rename()`（これが原子的な取り込み）→ 解放。取り込み以降の追記は、新しい `static_pending.json` に入るため、失われない。
  - 取り込んだファイルのページを再生成し、**成功したものだけ**を完了とする。取り込んだファイルは、すべて処理を終えてから削除する。失敗したページは `failed` として記録される（12.3）。
  - ビルドの開始時に、前回の異常終了で残った `static_pending.*.json` があれば、それも取り込む。
  - ビルドの完了直前にもう一度 pending を確認し、あれば同じ手順で処理する（なくなるまで繰り返す）。
- マニフェスト（`cache/static_manifest.json`）は、「一時ファイルへ書き出し → `rename()`」で更新する。内容: Wiki名ごとの出力パスと状態（`state`: `ok` / `failed` / `stale`）、この機能が作ったディレクトリの一覧（`dirs`）、添付ファイルとアセットの出力パス、全体生成の時刻（`built_at`）、全体の入力の記録（エンジンバージョン、スキン名など）。マニフェストは公開ディレクトリには置かない。
- ロックはエラー時を含め終了時に解放する。異常終了しても `flock` は OS が解放する。

### 12.8 出力の削除（無効化）

- 関数 `kona3static_purge()` は、マニフェストに記録した出力ファイルと、記録済みの生成ディレクトリ（空のもの）だけを削除する（12.1 と同じ規則）。出力先に他のファイルがあっても削除しない。ビルドロックを取得して実行する。
- 呼び出されるタイミング:
  - `wiki_private` が有効なときの、設定の保存・生成の実行・ページの保存（11章）
  - マイページの管理者メニューの「静的出力を削除」ボタン（`static_enable` がオフでも表示する。POST と CSRF トークン必須）
  - CLI: `php script/build_static.php --purge`
- `static_enable` をオフにしても、生成済みの出力は削除しない（オフにするだけで公開済みのサイトが消えるのを避けるため）。削除したい場合は上のボタンを使う。
- 削除後はマニフェストを空にする。

## 13. 設定項目

設定画面（ログイン後の「KonaWikiの設定」。`editConf` アクション）に、グループ「Static」（静的サイト）を追加する。次の3項目は設定画面で編集できる。

| キー | 型 | 既定値 | 説明 |
| --- | --- | --- | --- |
| `static_enable` | bool | `false` | 静的ファイルの生成を有効にする。オンのとき、編集時の1ページ生成と、マイページの生成ボタンが使える |
| `static_outdir` | string | `dist` | 出力先ディレクトリ。インデックスディレクトリからの相対パス、または絶対パス。保存時に 14章の安全確認を行い、不正な値は保存せずエラーにする |
| `static_base_url` | string | `/` | 公開URLのベース。サブディレクトリ公開は `/wiki/`、別ドメインは `https://example.com/wiki/` |

次の項目は、設定ファイル（`private/kona3conf.json.php`）を直接編集して指定する上級者向け設定とする（設定画面には出さない）。

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `static_exclude` | `["MenuBar"]` | 出力しないWiki名のプレフィックス |
| `static_plugin_disallow` | `[]` | 既定の C 分類に追加で無効化するプラグイン |
| `static_php_url` | `""` | PHP版のURL。指定時のみ静的版に PHP 版へのリンクを出す |

- `static_enable` を有効にしても、`wiki_private` が有効な場合は生成しない。設定画面に「Wiki Private が有効なため、静的ファイルは生成されません。生成済みの出力は削除されます（公開先に転送済みのコピーは別途削除してください）」と警告を出す。
- `static_outdir` の既定値 `dist` は、`.gitignore` に追加する（`/dist`）。別のディレクトリを指定した場合の `.gitignore` は利用者が管理する。
- 設定項目の追加に合わせて、`kona3conf_getConfigItems()` に定義を追加し、`lang/` の言語ファイルにラベルを追加する。

## 14. セキュリティ

- 出力先の安全確認: `static_outdir` の実パスが、`data/`、`private/`、`cache/`、`kona3engine/`、`skin/`、インデックスディレクトリそのもの、またはそれらの親ディレクトリ・配下であれば拒否する（ファイルの書き込みと削除を行うため）。設定画面での保存時と、生成の開始時の両方で確認する。
- 出力先の削除は、マニフェストに記録した、自分が生成したファイルと、自分が新しく作ったディレクトリに限る（12.1）。マニフェストに無いファイル・ディレクトリは削除しない。
- 利用者のファイルを上書きしない。書き込み先にマニフェストに記録のない既存ファイルがある場合（内容が同一の添付ファイルを除く）はエラーにする。ファイル内容の目印は所有権の根拠にしない（12.1）。
- Wiki を非公開にしたときは、生成済みの出力を削除する（11章、12.8）。
- すべての書き込み先について、実パスが出力先の配下にあることを確認する（パストラバーサル対策）。
- `data/` 内のシンボリックリンクはたどらない。
- 匿名ユーザー視点で描画し、ログイン情報・トークン・メールアドレス・設定値を出力しない。
- 添付ファイルは、拡張子が許可リスト（`allow_upload_ext`・`image_pattern`）に一致し、**かつ固定の拒否リストに該当しないもの**だけをコピーする。拒否リストは設定で変更できず、許可リストに含まれていても優先する。
  - 実行可能・サーバー側で解釈され得る拡張子: `php` `php3`〜`php8` `phtml` `pht` `phar` `phps` `cgi` `pl` `py` `rb` `sh` `asp` `aspx` `jsp` `shtml` `htaccess` `htpasswd`
  - 同一オリジンでスクリプトとして動き得る文書: `html` `htm` `xhtml`
  - 判定は小文字化した拡張子で行い、`a.php.jpg` のような多重拡張子は、途中の拡張子に拒否リストの項目が含まれる場合も拒否する。
- 静的版を PHP 版と同じオリジン（同じホスト名）で配信する場合、添付の SVG 等から PHP 版のセッションに影響が及び得るため、別オリジンでの配信を推奨する。
- マイページからの生成は管理者のみ、POST とCSRF トークン（`edit_token`）必須。`static_enable` がオフのときは実行しない。
- 編集時の1ページ生成は、ページ保存の権限があるユーザーのリクエストで実行されるが、描画は匿名ユーザーとして行い、ログイン情報を出力に含めない。

## 15. 実装構成

### 新規

- `kona3engine/kona3static.inc.php`
  - `kona3static_encodeName($name)` / `kona3static_decodeName($encoded)`: 4章の階層名エンコード
  - `kona3getStaticFile($wikiName)`: 出力パス（`dist/` からの相対）を返す。拒否条件ではエラー
  - `kona3getStaticURL($wikiName)`: 公開URLを返す
  - `kona3static_collisionKey($path)`: 衝突検出キー
  - `kona3static_buildPage($wikiName)`: 1ページ生成（編集時に呼ぶ）
  - `kona3static_buildAll($options)`: 全体生成（差分または全再生成）
- `kona3engine/action/static.inc.php`: マイページからの生成アクション（POST のみ、管理者のみ）
- `script/build_static.php`: CLI
- `kona3engine/tests/static_*.test.php`: テスト

### 既存の改修

- `kona3lib.inc.php`: `kona3getPageURL()`、`kona3getSkinURL()`、`kona3getResourceURL()`、`kona3getPageTitleLink()` の静的モード対応
- `action/show.inc.php`: `kona3show_render()` の切り出し、`exit` を伴う処理の例外化

- `action/edit.inc.php`: 保存成功後に `kona3static_buildPage()` を呼ぶ（`static_enable` のとき）。リネーム・削除時は旧出力を削除する
- `action/user.inc.php`、`template/user.html`: 管理者メニューに生成ボタンを追加（`static_enable` のとき）
- `lang/`: 追加した設定項目・ボタンのラベル
- `justfile`: `build` タスクを追加

## 16. テスト

| 観点 | 内容 |
| --- | --- |
| エンコード | 4.4 の変換例がすべて一致する。復号すると元に戻る |
| 予約名 | `CON` `con` `Com1` `NUL.txt` が回避される |
| 拒否 | 空の階層、`.`、`..`、不正な UTF-8、長すぎる名前がエラーになる |
| 衝突 | 大文字小文字違い、NFC/NFD 違い（例: `é` と `e` + `U+0301`）がエラーになる |
| URL | ベースURL `/`、`/wiki/`、`https://example.com/wiki/` で正しく生成される。FrontPage がベースURLになる |
| 出力 | 生成 HTML に `index.php?` が含まれない。編集ボタン・トークンが含まれない |
| リンク | `[[...]]` と Markdown リンク、パンくずが静的URLになる。存在しないページは `kona3_nolink` になる |
| 除外 | `.meta`、`"static": false`、`static_exclude` が出力されない。`wiki_private` ではビルドがエラーになる |
| 安全性 | 出力先が `data/` などの場合に拒否される。出力先の外に書き込めない |
| 状態 | 2ページ連続で描画しても CSS/JS タグやページ名が混ざらない |
| 設定 | `static_enable` の既定はオフで、オフのときは編集しても何も生成されない。`static_outdir` に不正な値（`data/` など）を指定すると保存できない |
| 編集時生成 | `static_enable` オンで1ページを保存すると、そのページの `index.html` だけが生成される。生成に失敗しても保存は成功する。リネーム・削除で旧出力が削除される |
| 差分 | ソースの mtime が出力より新しいページだけが再生成される。mtime が古いページは再生成されない。出力が無いページは生成される。メタデータの更新も検出される。設定・MenuBar・スキンの更新で全ページが再生成される |
| 強制 | 「すべて再生成」で、mtime によらず全ページが再生成される |
| 書き込み | 一時ファイルから `rename()` で置き換える。マニフェストにないファイルは、全体生成でも削除されない。出力先に既存の他ファイルがあっても残る |
| 排他 | ロック中の全体生成はエラーになる。ロック中の1ページ生成は pending に記録され、次の全体生成で反映される |
| 非公開化 | `wiki_private` を有効にして保存すると、記録済みの出力がすべて削除され、他のファイルは残る。以降の生成は行われない |
| 失敗の再試行 | 1ページの生成が失敗したあと、ソースと出力の mtime が「出力が新しい」状態でも、次の差分生成でそのページが再試行される。全体の入力の変更後に一部が失敗しても、`stale` のページが次回に再生成される。全ページが `ok` になるまで全体の入力の記録は更新されない |
| pending | ロック中に保存したページが、全体生成の取り込み中に追記されても失われない。異常終了で残った `static_pending.*.json` が次回に処理される |
| 上書き保護 | 利用者の既存ファイルと同じパスへの書き込みはエラーになり、ファイルは変わらない。生成物の印と同じコメントを含む利用者のファイルも、上書きされない。内容が同一の添付ファイルは上書きされず記録される。マニフェストを失った状態では、通常の生成はエラーになり、`--adopt --yes` を指定した場合にだけ置き換えられる。`--adopt` は管理画面からは実行できない |
| ディレクトリ | 生成前から存在していたディレクトリは、空になっても削除されない。この機能が作ったディレクトリは、空になったら削除される。出力先そのものは削除されない |
| ボタン | 管理者以外には生成ボタンが表示されない。GET や CSRF トークンなしの呼び出しは拒否される。`static_enable` がオフなら表示されず実行もできない |
| 正規化 | `intl` が無い環境ではビルドがエラーになる |
| 動的リンク | タグ表示が `plugin` アクションへのリンクにならない。`index.php?` が残る HTML はビルドエラーになる |
| 添付 | `allow_upload_ext` に `php` や `html` を加えても、それらはコピーされない |

## 19. フェーズ3の実装メモ

- 揮発ページの判定: 差分生成では内容を読まないため、描画時にソースを走査し、`recent` `recent_meta` `tag` `tags` `taglist` `filelist` `countpages` `ls` `include` のいずれかを含むページを `volatile` としてマニフェストに記録する。`volatile` のページ、ディレクトリ一覧ページ、エイリアスは差分生成でも毎回再生成する（`ls` と `include` は B 分類ではないが、ページの追加や他ページの更新で内容が変わるため、保守的に含める）。
- 「全体の入力」の記録はマニフェストの `inputs`（エンジンのバージョン、スキン名、設定ファイル・`MenuBar`・スキンと resource の最大 mtime）。1つでも変われば全ページを `stale` にして再生成する。
- 編集時の警告: Ajax 保存の JSON 応答に `warning` を含める。通常保存はリダイレクトのため画面には出さず、`cache/static_error.log` にのみ記録する。
- ページのリネームは現状の画面に機能がないため、削除（本文を空にして保存）の扱いのみ実装した。旧名の出力は次回の生成で削除される。
- `sitemap.xml` には KonaNotation / Markdown のページのみを載せる（ディレクトリ一覧・エイリアスは除く）。
