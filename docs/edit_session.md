# 編集中のセッション切れ対策 (Issue #64)

編集中にログインセッションが切れると、保存しようとしたときに
「未ログイン」や「編集トークンが不正」になって本文が失われる場合があった。
これを防ぐため、編集画面には次の3つの仕組みがある。

## 1. セッション維持 (keepalive)

編集画面を開いている間、JavaScript (`kona3engine/resource/edit.js`) が
5分おきに編集アクションへ `q=keepalive` で交信する。

- サーバー側はセッションの最終アクセス時刻を更新するので、
  ページを開いている限りセッションが GC で消えにくくなる。
- 「ログインを保持する (remember me)」の Cookie が有効なら、
  keepalive のリクエスト自体で自動ログインが働き、セッションが復活する。
- サーバーは現在の編集トークンを返す。トークンの有効期間 (1日) を
  過ぎていれば再発行したものを返すので、JavaScript がフォームの
  トークンを差し替える。これにより、長く開いたままのフォームでも
  トークンの期限切れで保存できなくなることがない。
  有効なトークンは毎回作り直さないため、別タブのフォームは壊れない。

## 2. セッション切れの検知と復旧 (Ajax保存)

一時保存・自動保存 (Ajax) が未ログイン (`nologin`) や
トークン不一致 (`invalid_token`) で失敗した場合、JavaScript は
本文を localStorage へ退避し、編集情報欄に再ログインへのリンク
(別タブで開く) を表示する。

- 再ログイン後、keepalive の交信間隔はセッション喪失中は短くなる
  (20秒おきに確認) ため、新しいセッションとトークンを自動で取り直し、
  未保存の変更があれば自動で保存し直す。
- Ajax の失敗時に待ち合わせフラグを解除するようにしたため、
  一度失敗しても以後の自動保存が止まることはない。

## 3. 保存できなかった本文の退避と復旧 (フォーム送信)

「保存して表示」のフォーム送信が未ログイン・トークン不一致で
失敗した場合、サーバーは送信された本文 (タグ・拡張子・記法モードを含む) を
セッションへ退避してからエラーを表示する (`kona3edit_stashRecovery`)。

- 退避の有効期間は編集トークンに合わせて1日。
- 再ログイン後に同じページの編集画面を開くと、退避した本文が
  ファイルの内容の代わりに表示され、復旧した旨のメッセージが出る
  (`kona3edit_getRecovery` / `kona3edit_applyRecovery`)。タグを全て消した
  場合の空文字も編集内容として復元される。競合判定用のハッシュは
  ファイルの内容から計算するため、復旧後の保存でも競合検出が正しく働く。
- 退避は表示しただけでは破棄されない (保存前に画面をリロードしても
  失われない)。保存に成功すると破棄される (`kona3edit_clearRecovery`)。
- セッション復旧後の自動再保存は最大3回までで、失敗が続く場合は
  ループにせず手動保存を促す。
- あわせて、フォーム送信時には JavaScript も本文を localStorage へ
  退避するので、セッション自体が失われた場合でも編集画面の
  「一時保存を読込」から本文を取り戻せる。
