# ページ名・タイトル名の文字数制限

Issue #133 の確認結果と、導入した制限についてまとめます。

## 確認した従来の仕様

従来は、ページ名(タイトル名)には文字数制限が一切ありませんでした。

- `kona3parseURI()` は長さに関係なくページ名を受け付けます
  (テスト `kona3lib_uri.test.php` にも「1000文字のページ名も処理可能」という確認があります)。
- SQLite の `pages.name` は `TEXT` 型で長さの上限はありません。
- しかしページ名はそのまま `data/` 以下のファイル名になるため、
  多くのファイルシステムでファイル名の上限である255バイトを超えると、
  保存時に「ファイルに書き込みができません」という分かりにくいエラーになっていました。
  日本語は1文字3バイト (UTF-8) なので、例えば82文字のページ名でも保存できませんでした。

## 導入した制限

新規ページの作成時 (「新規」アクション) と、ページの保存時 (編集アクションで
新規ファイルを作るとき) に、次の2つを確認します。
問題がある場合は理由を表示して作成・保存を中止します。勝手に切り詰めることはしません。

| 制限 | 既定値 | 備考 |
|---|---|---|
| ページ名全体の文字数 | 200文字 | 設定 `page_name_max_length` で変更可能。0以下で無制限。文字数は `mb_strlen` で数える (日本語も1文字は1文字) |
| ページ名の各階層 (`/` で区切った各部分) のバイト数 | 245バイト | 設定によらない固定値。ファイル名の上限255バイトから拡張子 (`.txt`/`.md`/`.json`/`.html` など) の分を差し引いたもの。`enc_pagename` が有効なときは、実際に保存される `urlencode` 後の名前で数える |

判定は `kona3validatePageName($page)` (問題なければ空文字列、あれば理由を返す) と
`kona3isValidPageName($page)`、`kona3getPageNameMaxLength()` で行います
(`kona3engine/kona3lib.inc.php`)。

## 既存ページへの影響

制限は新規作成のときだけ適用します。

- 上限を超えた名前の既存ページも、これまでどおり表示できます
  (`kona3parseURI()` には制限を入れていません)。
- 既存ページの編集・保存も、上限を超えた名前のままで行えます
  (保存時の確認は、対象ファイルがまだ存在しない場合だけ行います)。

## テスト

`kona3engine/tests/page_name_length.test.php` で、境界値 (200/201文字、
243/246バイト)、階層ごとの判定、設定による上限の変更、
`enc_pagename` 有効時の判定を検証しています。
