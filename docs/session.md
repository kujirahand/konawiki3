# セッションの設定 (Issue #386)

KonaWiki3 のセッションは、ログインフォームや編集フォームのトークン (有効期間1日) の保管にも使われます。そのため、セッションの寿命もトークンに合わせて1日に揃え、保存先を Wiki 専用にして OS の掃除処理や他のアプリの影響を受けないようにしています。

## 設定項目

管理画面の基本設定 (Basic) で変更できます。

| 設定 | 既定値 | 意味 |
|---|---|---|
| `session_name` | `kona3session` | セッション Cookie の名前。既定値のまま使う場合、実際の名前には Wiki ごとに異なる接尾辞が付き、同一ホストに複数の Wiki を置いても衝突しません。明示的に変更した場合はその名前をそのまま使います。複数の Wiki で同じ名前を明示すると Cookie が互いに干渉し、ログイン状態やトークンが上書きされるため、Wiki ごとに別の名前にしてください |
| `session_lifetime` | `86400` (秒) | セッションの保持期間 (サーバー側と Cookie の両方)。この値より短くすると、その時間が過ぎたフォームの送信時に「ログインセッションの有効期限が切れています」となり、1回目のログインが失敗します |
| `session_persistent_cookie` | 有効 | 無効にすると Cookie はブラウザを閉じるまでになり、ブラウザ再起動後はログイン状態もフォームのトークンも引き継がれません |
| `session_save_path` | 空 | 空の場合は `private/sessions` を使います。`php` と書くと php.ini の保存先に戻ります (問題の切り分け用)。それ以外は指定した絶対パスを使います。相対パスは使えません。指定した場合は無視され、php.ini の保存先が使われます |

## 動作の注意

- ログアウトせずにブラウザを閉じても、`session_lifetime` の間はログインが残ります。共用端末ではログアウトしてください。
- 使用中は Cookie の期限が (1時間に1回まで) 延長されるため、使い続けている間は切れません。無操作が `session_lifetime` 前後続くと切れ、再ログインが必要になります。その際に編集中だった本文は、編集画面の本文退避 (#64) で保護されます。
- 別のタブでログインやログアウトをした後に残っている古いフォームは、安全のためトークン不一致で拒否されます。再表示されたフォームから送り直してください。

## Apache 環境での注意

- セッションの設定はコード側で行うため、mod_php でも PHP-FPM でも同じように効きます。`.htaccess` の `php_value` は使いません (PHP-FPM 構成ではエラーになります)。
- `private/sessions` にはアクセス拒否の `.htaccess` が自動で置かれますが、`AllowOverride None` の環境では効きません。導入時は `https://<ホスト>/<Wiki>/private/sessions/` にアクセスして 403 になることを必ず確認してください。ならない場合は VirtualHost の `<Directory>` で遮断するか、`session_save_path` で公開領域外のパスを指定してください。
- nginx は `.htaccess` を読まないため、`private/` 以下を設定で遮断してください。例: `location ^~ /private/ { deny all; }` (Wiki をサブディレクトリに置く場合は `/<Wiki>/private/` にします)。空の `index.html` も置かれますが、これはファイル一覧の表示を防ぐだけで、`sess_` ファイルへの直接アクセスは防げません。
- 保存先を作れない・書き込めない場合 (フォールバック時) や `session_save_path` を `php` にした場合は、php.ini の保存先を使うため、OS の掃除処理 (sessionclean 等) の影響を受けます。この場合、`session_lifetime` どおりの保持期間は保証できません。
- VirtualHost や PHP-FPM のプール設定で `session.*` に `php_admin_value` が指定されていると、コード側の設定よりそちらが優先されます。
- バックアップとデプロイ (rsync 等) では `private/sessions` を除外してください。消すと全員がログアウトします。
- TLS をプロキシで終端する構成では Cookie の Secure 属性が付きません。必要な場合は Apache 側で `SetEnv HTTPS on` を設定してください。
