# セキュリティ監査 (#324)

2026-10-25 に実施した定期セキュリティ監査の記録。
対象はプラグイン全般 (特に comment / counter・count系 / ls)、
アクション全般 (特に resource / show)、およびコア (パーサー /
テンプレートエンジン / DB層)。再現できた問題だけを修正し、
回帰テストを `kona3engine/tests/security_audit_324.test.php` に追加した。

## 修正した問題

### プラグイン

1. **comment: 掲示板管理パスワードの既定値が公開コード中の固定値だった (高)**
   - 既定値を空 (無効) に変更。旧既定値が設定ファイルに残っている場合も
     未設定として扱い、`hash_equals` で照合する。
2. **qrcode: 引数が `<script>` 内のJS文字列を抜け出す保存型XSS (高)**
   - テキストを `json_encode` (HEX系フラグ付き) で埋め込むよう変更。
3. **color_talk: 色指定が style 属性を抜け出す保存型XSS (高)**
   - 色として正しい形式 (#hex / 色名 / rgb() 等) の値だけを受け付ける。
4. **include / file: 自己・相互参照で無限再帰しメモリ枯渇する (中)**
   - 両プラグインで共有する深さ制限 (5段) を追加。
5. **file / filecode / include: data内のシンボリックリンクで外のファイルを読めた (低)**
   - 実パスが data ディレクトリ配下の通常ファイルであることを確認してから読む。

### アクション

6. **search: 非公開Wikiで未ログイン検索でき、ページ名列挙と本文の存在確認ができた (高)**
   - show と同じ非公開チェックを追加。
7. **data: 添付SVGがスクリプト実行可能な形で配信されていた (高)**
   - SVG配信に `Content-Security-Policy: sandbox` と
     `X-Content-Type-Options: nosniff` を付与 (skin のSVGも同様)。
   - data配下のシンボリックリンクによる外部読み取りを防止し、
     非画像ファイルも拡張子から固定のContent-Typeで配信。
8. **attach: CSRFトークンが無かった (中)**
   - アップロードに `edit_token` を必須にし、フォームにも埋め込んだ。
9. **update_page_history: 全削除がGET・トークンなしで実行できた (中)**
   - 全削除リンクにトークンを付け、実行前に検証する。リンクURLの
     エスケープ漏れもあわせて修正。
10. **emailLogs: 全削除の根拠が推測可能な時刻だけだった (中〜低)**
    - 確認リンクにトークンを付け、実行前に検証する。
11. **versionup: データ移行を一般ユーザーが実行できた (中〜低)**
    - 管理者のみに変更し、移行案内も管理者にだけ表示する。
12. **user / plugin: 非公開Wikiで未ログインでも情報が見えた (中〜低 / 低)**
    - show と共通の `kona3show_check_private()` による非公開チェックを追加 (plugin は入口で一括遮断)。
13. **skin: 他スキンのテンプレート (.tpl.php) のソースが取得できた (低)**
    - 配信できる拡張子を css/js/画像/フォント等に限定。

### コア

14. **テンプレートエンジン: `extract()` で `$file_cache` を上書きし任意ファイルを include できた (中・潜在)**
    - キャッシュ経路でも退避変数を確定してから include し、
      `extract()` は `EXTR_SKIP` に変更。現行の呼び出し元では
      リクエスト由来のキーは渡らないため潜在的な問題だった。

## 問題なしを確認したもの

- comment / counter / count / ls のXSS・SQLインジェクション・CSRF
  (comment の状態変更は全てトークン検証あり、検索系は prepared statement、
  ls は realpath + 配下チェック済み)
- resource / show / text のパストラバーサル、go のオープンリダイレクト
- 自動リンク・ref・image のスキーム注入 (`javascript:` 等は無害化される)
- html / htmlshow プラグイン (既定で `plugin_disallow` により無効)

## フォローアップ (別Issue #325 で対応)

- signup の認証コード: 有効期限・試行回数制限がなく、未認証アカウントの
  パスワードを再登録で上書きできる。認証メール再送も無制限。
- login: 試行回数制限 (スロットリング) がない。
- comment の todo 切替: ログイン済みなら他人のコメントも切替できる
  (協調利用の仕様か確認が必要)。
- pdf: `use_pdf_out` 設定の強制がコード上は無い (TCPDF未配置環境では未検証)。
- mermaid のSVG検証: ブラックリスト方式で素通りする入力が2種あった
  (ブラウザでの発火は未確認)。
- 全削除操作 (update_page_history / emailLogs) がトークン付きGETリンク
  (PR #326 の agy レビューで追記)。

## フォローアップ #325 の対応結果

- **signup**: 認証コードに有効期限 (発行から30分) と試行回数制限
  (5回失敗でコードを無効化) を追加。未認証アカウントが既にある場合は
  再登録で name/password/token を上書きしない (認証か再送で完了する)。
  ただし有効期限が切れた未認証行は削除して再登録を受け付ける
  (期限切れ行が残り続け、そのメールアドレスで登録できなくなるのを防ぐ)。
  再送は POST 化し、60秒の間隔制限と CSRF トークン (`signup_token`) を追加。
  登録・照合も同じトークンを必須にした。
- **login**: 試行回数制限を共通関数 (`kona3loginThrottle*`) として実装。
  meta テーブルの `login_error` 行で失敗を記録し、同じ IP+ユーザー で
  10分間に5回、同じ IP 全体で20回失敗したら、期間内はパスワードを
  照合せず `throttled` を返す。成功時はその IP+ユーザー の記録を消す。
  2024年に導入した制限が #132 の書き換えで落ちていたことの復旧でもある。
- **comment の todo 切替**: 協調利用が意図した仕様であると確認し、明記した。
  todo は Wiki 上の共有タスクであり、切替は可逆で内容も失われないため、
  ログイン+トークンがあれば投稿者以外でも切替できる。一方、削除は
  不可逆なので投稿者本人/管理者のみに制限する。この非対称は仕様であり、
  プラグインの docblock にも明記した。
- **pdf**: アクション側でも `use_pdf_out` を確認し、無効なら TCPDF の
  読み込みもフォントのダウンロードも行わずに終了するようにした。
- **mermaid**: SVG検証を構造的検証に強化。XML として走査し、危険な要素
  (`script` / `foreignObject` / `image` など) を拒否し、属性値は実体参照の
  デコードと制御文字除去で正規化してから `href` 系と `style` を検証する。
  これで data: URI の入れ子 SVG 画像と、タブ分割した `javascript:` href の
  2種の素通りを塞いだ。
- **全削除のPOST化**: `update_page_history` の履歴全削除と `emailLogs` の
  ログ全削除を、トークン付き GET リンクから POST フォーム (確認画面付き)
  に変更し、実行側も POST のみ受け付けるようにした。

回帰テストは `kona3engine/tests/security_followup_325.test.php`。
