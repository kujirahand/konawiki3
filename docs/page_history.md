# 編集履歴 (page_history) について

ページの編集履歴は SQLite (`private/info.sqlite`) の `page_history`
テーブルに保存され、編集画面下部の「履歴」ボタンから一覧できます。
履歴のリンクを開くと、その時点の本文が編集画面に表示されます
(表示しただけではページは変更されません。保存すると現在の本文として
書き込まれます)。

## 履歴の保存

- ページを保存するたびに `kona3db_writePage()` が履歴を記録します。
- 同じユーザーが1時間以内に続けて保存した場合は、履歴を増やさず
  直近の履歴を更新します。
- ページを削除 (本文を空にして保存) しても履歴は削除されません。

## 履歴が見えない場合 (#46)

履歴は `page_id` でページと結び付けられています。そのため、
`pages` テーブルの ID と食い違う ID で履歴が登録されていると、
DB に履歴が残っていても一覧に出てきませんでした。食い違いは
旧方式の ID 管理 (`.kona3_page_id.json` のレガシーID) や、
後述の再登録ツールの独自 ID 割り振りで起きていました。

現在の実装では:

- `kona3db_getPageHistory()` は、現在の `page_id` に加えて
  そのページ名に対するレガシーIDの履歴も合わせて表示します
  (`kona3db_getPageIdsForHistory()`)。
  ただしレガシーIDが別ページに割り当て済みの場合は混ぜません。
- 履歴の表示/削除リンクは GET で `edit_token` を渡します。
  トークン照合は POST を優先し、POST がなければ GET を見ます
  (`kona3_checkEditTokenReason()`)。
  以前は POST しか見なかったため、削除リンクが常に
  Invalid Token になっていました。

## ファイルから履歴を再登録する (update_page_history)

管理者 (user_id=0) で `index.php?ページ名&update_page_history` を
開くと、`data/` 以下のページファイル (.txt / .md、サブフォルダ含む)
を走査して、現在の本文を履歴として登録します。

- `page_id` は通常の編集と同じく `kona3db_getPageId()` で取得し、
  `pages` テーブルに統一します。レガシーJSONへ独自 ID を
  書き込むことはありません。
- 同じページ・同じ更新日時・同じ本文の履歴が既にある場合は
  スキップします (旧方式の ID で登録済みのものも含みます)。
- `?clear=all` を付けると `page_history` を全削除してから
  登録し直します。
